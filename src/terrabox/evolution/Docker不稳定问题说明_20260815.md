# Docker 事故与修复记录

> 更新时间：2026-08-17。本文记录 2026-08-15 前后的 Docker 故障及当前修复状态，不代表当前正式 OEA 实验仍处于故障状态。

## 曾出现的问题

- Docker daemon 控制面偶发 `create/start/inspect` 超时、`context canceled`，容器状态与实际可用性不一致；
- 容器内 DNS 查询超时，导致感知服务冷启动或外部请求异常；
- 历史上曾将默认 runtime 设为 `nvidia`，导致非 GPU 容器也走 NVIDIA runtime，放大容器创建和 GPU 服务重建的不确定性；当前 daemon 默认 runtime 为 `runc`，GPU 容器由 manager 显式传 `--gpus device=...`。
- 多个 rollout worker 同时重建或抢占感知服务时，可能造成超时、GPU OOM 或异常期结果污染。

## 已完成修复

- Docker 版本为 `27.5.1`；daemon 默认 runtime 为 `runc`；已验证 `runc + --gpus device=3` 可以启动 CUDA 容器并正确识别 RTX 3090。不建议把全局默认 runtime 改回 `nvidia`，因为这会影响 CPU/非 GPU 容器；需要 GPU 时使用显式 `--gpus`。
- daemon DNS 已配置为 `223.5.5.5` 和 `119.29.29.29`，不依赖 localhost DNS。
- Qwen3-VL 固定 GPU0，使用 `VLM_MAX_MODEL_LEN=8192`、`VLM_MIN_IMAGE_MODEL_LEN=8192`、`VLM_GPU_MEMORY_UTILIZATION=0.95`、`VLM_MAX_NUM_SEQS=1`；`0.90` 会造成 KV cache 不足，不应回退。
- InstructSAM 固定 GPU3，在正式 GPU lane 启动前完成健康检查与预热；其它重服务维持 call-scoped，并由跨进程服务锁串行化。
- InstructSAM 的 `docker create/start` 仍受 `TERRABOX_DOCKER_START_TIMEOUT_SECONDS` 限制；模型健康检查使用 `TERRABOX_INSTRUCTSAM_STARTUP_TIMEOUT_SECONDS`，默认 420 秒。首次 SAM2/GeoRSCLIP 加载可能接近 3 分钟，不能再用 120 秒固定上限判断启动失败。
- 外部 API OEA 实验按 GPU/no-GPU 分 lane：GPU lane 单 worker，no-GPU lane 多 worker；避免多个 worker 抢同一感知服务。

## 复验结论

`expevo_v4_clean_dockerfixed_20260816` 已完成 OEA test 1162/1162；其正式 rollout 期间未观察到 Docker `context canceled`、CUDA OOM 或容器启动失败，且 InstructSAM 工具调用返回成功。该实验之后的 P0 队列预热失败，直接原因是 manager 原先在约 120 秒健康等待后主动清理仍在加载模型的容器；不是 `runc` 无法使用 GPU。修复后若健康检查超时，manager 会记录 `docker inspect` 和最近 120 行容器日志，再清理本实验容器并停止 watcher。

GPU 服务显存常驻但利用率较低是预期现象：主 agent 走 LongCat API，且部分感知调用命中工具缓存；不能以瞬时 GPU utilization 为健康性或吞吐量的唯一依据。

## 后续运行要求

- 正式 watcher 先预热并检查服务；预热失败则退出，禁止静默降级或把半启动服务带入正式结果。
- GPU 运行时约定：保持 daemon 默认 `runc`，GPU 服务显式传 `--gpus device=...`；除非单独验证某个服务确实需要，否则不要通过 daemon 全局默认 `nvidia` 修复问题。
- 不设置 `TERRABOX_TOOL_GPU_DEVICES`，它会覆盖 per-service 钉卡。
- 保持 `TERRABOX_TOOL_SERVICE_SCOPE=call` 和 `TERRABOX_KEEP_VLM_WARM=1`；有独占 GPU 的正式 lane 才可保持 InstructSAM warm。
- 若再次出现连续 Docker 控制面错误、DNS 故障或 OOM，暂停受影响 lane，在新结果目录重跑，不能与修复后的结果混合。
