## EarthBench 状态

- EarthBench no-GPU 尝试已停止：EB 理论上仍可能需要 raster/感知/地理数据处理，不适合当作“不占 GPU”的夜间并行任务。
- 已处理数据缺口：`data/earthbench/question_data -> /data1/yuhongjie2/terrabox_bak/data/earthbench/question_data`。
- 停止前只有极小样本探针：base 第 1 条 `earthbench_63_v4` 反复调用 `bash.execute` 并撞 max-turn；v3 同任务能推进到 `earth_sci.calculate_pwv` 并完成。样本太少，不能作为结论。
- 后续如果跑 EarthBench，应单独排资源队列，不和 OEA/tau2 低优先级支线混跑。

## 当前结论

- ExperienceEvo v3 的工具链确实更“短、准、稳”：set/multiset F1、exact、ordered exact、LCS、工具类别 F1、工具错误、重复调用、耗时和 token 成本都优于 LongCat base。
- 但 v3 的最终答案质量明显低于 base/MemRL/Reflection，尤其生成类任务 `answer_acc_w_gen` 掉得很重；这说明当前 v3 不能直接作为论文主结果收口。
- 最可能的问题不是“经验完全没用”，而是经验/guard 把 agent 推向过早收敛：工具序列接近 gold，但 final answer synthesis、生成类最后工具或必要的补充调用被压掉。
- 下一步主线应先做 v3 失败日志诊断与消融：`no_store`、`store_only`、`soft_only`、`answer_ready_off`、`quse_off`，再决定是否改 v4。
- tau2 可以继续低优先级跑，用来补非地理工具场景的数据量；OEA 仍是中期答辩主线。
