# ExperienceEvo：产物状态转移经验自进化方案

> 当前实现口径：`v4-clean` 为严格主方法；`v5` 是 2026-08-22 新增的最终答案证据校验增强版，实验中。
>
> 本文描述正式方法；早期 v1-v4 设计草稿见 `文档归档/20260817_实验文档整合前/经验自进化_产物转移方案_20260731.md`。

## 问题与核心思想

多工具 agent 的失败通常不是缺少某条完整案例，而是不知道在当前产物状态下应该得到什么中间产物、哪些工具可完成该转移、以及某个工具的参数和风险约束。ExperienceEvo 因而不直接检索原始完整轨迹，而是将 rollout 拆为可复用的**产物状态转移经验**。v5 在此基础上增加最终答案证据校验：不改变经验库和工具规划逻辑，而是在 agent 准备输出 final answer 前，由 verifier 子 agent 检查当前运行已经产生的 artifact、layer、工具 observation 是否支持答案中的数值、单位、阈值、计数和实体选择。

产物状态转移经验的核心结构如下：

```text
任务与当前 artifact state
  -> 预期的下一产物/状态
  -> 可实现该状态转移的候选工具
  -> 参数、前置条件、风险和恢复约束
```

同一目标转移可以由多种工具实现。经验的目标是指导下一步决策，而不是把某条历史轨迹复制到当前任务。

## 严格数据边界

### 建库可见信息

- train 任务文本、输入文件、公开工具说明；
- LongCat Base rollout 中实际发生的工具调用、参数、observation、产物与自然语言回答；
- 可观测执行信号，例如工具显式参数错误、缺失输入或不满足前置条件。

### 禁止信息

- `task_type`、`expected_tools`、gold trajectory、gold answer、task id；
- OEA tool F1、answer judge 或任何 gold 反馈；
- eval 任务的标签、轨迹和结果。

基础设施故障（网络、Docker、OOM、provider、quota、上下文限制）不归因给经验，也不提高 risk；它们只会被记录或由实验 runner 按策略重试。

## 离线建库链路

```text
train task
  -> LongCat Base rollout
  -> 从每个实际工具调用抽取
       (pre-state, intent, tool, arguments, observation, post-state)
  -> 归一化 artifact/state/intent，聚类为 TransitionFamily
  -> 对每个 family 聚合工具级统计和自然语言经验
  -> JSONL + SQLite store
```

一个 family 的逻辑结构如下：

```text
任务/意图：从 31/32 波段与发射率得到 LST 栅格
前置产物：band_31, band_32, emissivity
目标产物：LST raster
工具候选：tool_A / tool_B
工具约束：输入文件角色、关键参数、输出产物、已知风险、恢复建议
```

store 同时保留：

- **签名/产物级统计**：`Qsig`、`Nsig`、`Rsig`，衡量该状态转移经验的稳定性、样本数与风险；
- **工具级统计**：`Qtool`、`Ntool`、`Rtool`，衡量某工具实现该转移时的稳定性、样本数与风险；
- **蒸馏经验文本**：前置条件、目标产物、参数/产物约束、风险和恢复提示；
- 原始 rollout event 的审计引用，不在 eval prompt 中直接作为案例轨迹注入。

在观察到可归因的 agent 决策错误时，统计以衰减更新：

```text
Q <- Q + alpha * (r - Q)
R <- R + alpha_risk * (risk_observed - R)
N <- N + 1
alpha = alpha_0 / sqrt(N + 1)
```

`risk_observed=1` 只表示可归因的工具/参数/前置条件选择错误；不把基础设施不稳定混入风险。

## Eval 运行时链路

```text
eval task + 当前 artifact state
  -> query/state/intent 检索 transition families
  -> 产物级软提示：下一步应该产出什么及其前置条件
  -> 候选工具级重排：Quse + risk + 参数约束
  -> LongCat 选择工具和参数并执行
  -> 更新 artifact state
  -> soft verifier 检查当前目标是否已充分满足
  -> v5 可选 final-answer verifier 检查最终答案是否被当前证据支持
  -> 可选 checker 子 agent 复核高风险/低置信决策
  -> 直到输出最终答案
```

检索使用任务文本、当前状态与意图的 lexical/结构化混合检索：BM25 与 typed state/intent 的候选排序通过 RRF 融合，再以工具级质量与风险重排。它不以 `task_type` 或 gold 工具作为分桶、索引或过滤条件。

在一个被选中的 family 内，工具使用分数为：

```text
Quse = lambda * Qtool + (1 - lambda) * Qsig
lambda = Ntool / (Ntool + k)
```

经验只以 soft guidance、候选排序、参数约束与恢复提示影响 agent；agent 仍可选择未推荐工具。这样可避免把错误经验变成硬规则，也允许跨任务复用同一状态转移。

## 多 agent 校验位置

默认 v4-clean 主流程含 soft verifier。对低 `Quse`、高 risk 或明显违反转移约束的调用，可启用 checker 子 agent：它检查参数角色是否颠倒、已有中间产物是否被使用、输出是否真正满足目标，并提供 recovery hint。

v5 新增的 final-answer verifier 是另一个轻量子 agent。它不看训练轨迹、gold、`task_type` 或 task id，只看本次运行的 artifact state、成功/失败工具调用、observation 和 draft answer；若发现答案未被证据支持，会把证据摘要和修正提示回注给主 agent，让主 agent 再回答或补一次必要工具调用。

checker 和 final-answer verifier 都是可消融模块，不应默认宣称其带来收益。只有对应对照完成后，论文才可以将多 agent 校验作为量化贡献；否则表述为系统支持的可选安全机制。

## 版本差异

| 版本 | 特征 | 是否可作严格主表 |
|---|---|---|
| v3 | hard answer-ready/synthetic final，容易过早终止 | 否，历史诊断 |
| 历史 v4 | soft step hint、Quse、soft verifier；曾使用 `task_type` family 信息 | 否，过渡结果 |
| v4-clean | 无标签 rollout-only store；混合检索、Quse/risk、soft verifier、可选 checker | 是，当前严格主方法 |
| v5 | v4-clean + artifact-state evidence summarizer + final-answer verifier | 实验中；若全量结果稳定，可作为候选主方法 |

## 实现位置与使用

- v4-clean runtime：`experience_evo/v4_clean/runtime.py`
- v5 runtime：`experience_evo/v5/runtime.py`
- store 构建与实验工具：`experience_evo/v4_clean/`
- 统一入口：`get_prompt_augmenter("experience_evo_v4_clean", ...)` 或 `get_prompt_augmenter("experience_evo_v5", ...)`
- 当前 store：`evolution_store/experience_evo/oea_train2000_v4_clean_longcat_20260814/`
- 评测与运行约束：`经验自进化_中期答辩实验代办_20260805.md`、`AGENTS.md`

接口为兼容既有 agent 可能接受 `task_type` 参数，但 v4-clean/v5 runtime 会忽略它。正式实现和实验不得重新把该字段用于经验建库、检索、verifier 或 prompt。

v5 运行示例：

```bash
PYTHONPATH=src python scripts/run_trajectory_experiment.py rollout \
  --task-file data/oea_full_sft/openearth_test_tasks.json \
  --experiment experience_evo_v5_full_dockerfixed_20260822 \
  --mode standard \
  --llm-provider longcat \
  --evolution-method experience_evo_v5 \
  --evolution-store evolution_store/experience_evo/oea_train2000_v4_clean_longcat_20260814 \
  --use-docker --resume
```

需要关闭 v5 最终答案 verifier 做 sanity check 时设置：

```bash
export TERRABOX_EXPEVO_V5_DISABLE_FINAL_VERIFIER=1
```
