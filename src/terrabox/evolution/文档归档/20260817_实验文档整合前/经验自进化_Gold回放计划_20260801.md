## 1. Gold 参数能不能给 LLM 看

结论分三层：

1. **eval / test-time agent 不能看 gold 参数。**  
   `gold_tool_calls.arguments`、`expected_tools`、`ground_truth` 都是 teacher / label 信息。
   如果把它们放进 LongCat agent prompt，测试就变成 oracle replay，不再是工具使用能力评估。

2. **offline teacher-forced executor 可以使用 gold 参数。**  
   gold replay 的目标是验证“标注轨迹本身是否能在当前工具栈执行”。这里参数只交给工具执行器，
   不交给做题 agent；这属于数据审计 / teacher upper-bound。

3. **LongCat 蒸馏器只能看脱敏后的 replay 证据。**  
   构建 gold-derived store 时，LongCat 可以看：
   `任务意图类别 + 输入产物签名 + 输出产物签名 + 工具名 + 参数绑定规则 + observation 摘要 + 成败证据`。
   不能看 task id、gold answer、精确历史路径、具体地点名、具体 layer 名或可直接复现单条题目的自由文本参数。

## 2. Gold 数据目前是否对齐

静态转换口径看，OEA full SFT 的 gold 已经基本对齐当前 Terrabox schema：

```text
-----------------------------+-------------------------------+
| train rows                  | 14538                         |
| rows with gold_tool_calls   | 14538                         |
| unique gold tool sequences  | 87                            |
| adapted gold arguments      | 71578                         |
| conversion warning rows     | 3                             |
| tool coverage               | 23 / 23 OE tools              |
+-----------------------------+-------------------------------+
```

但“静态 schema 对齐”不等于“真实 replay 一定正确”。仍需要实跑验证：

- gold 里的 `gpkg_N`、`tif_N`、`img_N` 等是 OEA symbolic artifact alias，需要按样本输入和前一步 observation 动态绑定；旧版 replay 未完整绑定时产生的 `GeoPackage not found: gpkg_1` / `Raster file not found: tif_1` 应归为 harness gap，不应直接判成 gold 顺序错误；
- OSM/STAC/Bing/感知服务可能因为外部服务、缓存、模型版本变化造成 observation 不一致；
- 部分 gold 参数虽然 schema 合法，但可能不是当前工具实现下最稳的参数；
- final answer 是否能由 replay observation 推出，还需要 answer/judge 验证。

所以 gold 不能直接进入主 ExperienceEvo store，必须先做 replay audit。

## 3. 推荐实验矩阵

```text
+----------------------+----------------------+----------------------+--------------------------+
| 实验                 | 经验来源             | eval agent 是否看 gold | 论文定位                 |
+----------------------+----------------------+----------------------+--------------------------+
| LongCat base          | 无                   | 否                   | ReAct / no-memory baseline|
| rollout-v2 store      | train LongCat rollout| 否                   | 主 self-evolution 方法    |
| gold-replay store     | train gold replay    | 否                   | teacher upper-bound 诊断  |
| gold+rollout mixed    | 两者分开标注后混合   | 否                   | 可选消融                 |
| test gold replay      | test gold replay     | 不涉及 agent         | 数据可执行性审计，不进主表|
+----------------------+----------------------+----------------------+--------------------------+
```

正式论文主表不要把 gold-derived store 和 rollout-derived store 混成同一个方法。gold replay store
更适合回答两个诊断问题：

- 如果 gold 轨迹真实可执行，ExperienceEvo 的上限大概是多少？
- 如果 gold store 也不提升，是检索/注入/产物转移建模的问题，而不只是 train rollout 质量差。

### G1. Gold replay smoke

目标：抽样 `50-100` 条 train，优先覆盖 87 个 gold sequence 中的低频/复杂序列。

执行方式：

- 不让 LongCat 选择工具；

- 工具 observation 后维护 artifact binding map；
- 对 replay 成功样本，用 LongCat 只做 final-answer summarizer / checker；
- 对 replay 失败样本分桶，不更新 ExperienceEvo Q/R/N。

验收：

- replay success rate；
- schema/binding failure rate；
- infra failure rate；
- LongCat final answer judge；
- 典型失败日志 10 条人工看。

### G2. Gold replay train2000

目标：在 smoke 通过后，对当前同一 train2000 subset 做 gold replay，保证和 rollout-derived v2
使用相同 train task source。

选择策略：

- 继续使用 “覆盖不同 gold tool sequence，再 seed shuffle 填满 2000”；
- 如果 smoke 显示某些 sequence replay 大量失败，保留失败桶，不静默删掉；
- infra failure 可以有限重试；schema/binding/参数语义问题不重试。

资源策略：

- LongCat 只用于 answer/checker/distill，不做 actor；
- 工具 replay 仍按 OEA 三流思想拆：
  - P0：GPU0/1 感知 lane；
  - P1：GPU2/3 感知 lane；
  - OSM/nogpu：网络/CPU lane，误调感知时走已有 lane lock；
- 外部 API 三流仍使用 `TERRABOX_TOOL_SERVICE_SCOPE=call` 与
  `TERRABOX_KEEP_VLM_WARM=1`；
- 绝不设置 `TERRABOX_TOOL_GPU_DEVICES`。

### G3. 构建 gold_replay_store

目标：只从 replay 成功或可局部验证成功的 transition 构建 store。

store 建议路径：

```text
evolution_store/experience_evo/oea_train2000_gold_replay_v2_longcat_20260731/
```

关键限制：

- JSONL 中标明 `source_type=gold_replay`；
- 不写入 eval/test gold；
- 不写入原始 task id / gold answer / 精确路径 / 具体地点；
- 不覆盖 rollout-derived v2 store；
- prompt runtime 继续走 `experience_evo_v2`，只换 `--evolution-store`。

### G4. Gold-store eval

目标：用 LongCat actor 在 OEA test 1162 上评估 gold-derived store。

对比：

```text
LongCat base
rollout-derived ExperienceEvo v2 train2000 store
gold-replay ExperienceEvo v2 train2000 store
optional mixed store
```

指标：

- answer accuracy / judge；
- set-F1、multiset-F1；
- AnyOrder / SameOrder / Unique；
- per-category F1；
- tool error rate、max-turn rate；
- Quse 命中率、经验采纳率、prompt token 增量；
- 长尾工具和未见工具组合表现。

### G5. Test gold replay audit

目标：验证“测试集 gold 轨迹本身是否在当前工具栈可执行”。

注意：

- 这不是方法训练，也不是经验来源；
- 不把 test gold replay 结果蒸馏进任何 eval store；
- 只输出数据可执行性报告，帮助解释指标上限。

如果 test gold replay 本身成功率低，说明 OEA gold 与当前 Terrabox 工具栈存在口径/服务/动态绑定问题；
如果 test gold replay 高而 agent 低，说明主要问题是 agent 的工具选择、参数绑定和中间产物消费。

## 7. 我推荐的结论口径

- 主方法仍应是 **rollout-derived offline self-evolution**：agent 不看 gold，只从自己的 train rollout
  里沉淀产物转移经验，然后到 test 上只读检索。
- gold replay 是必要的 **teacher upper-bound / data validity audit**：它能判断当前提升小是不是因为
  train rollout 质量太差，还是因为经验建模/检索/注入没打中。
- GRPO/RL 阶段不建议只用 gold。gold 适合 SFT/warm-start 和 verifier 校准；GRPO 主体应使用当前策略
  on-policy rollout，并把 answer judge、tool status、product validity、schema validity 组合成 reward。
