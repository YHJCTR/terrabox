## Phase 3 - Reward 和 Risk 评分

- [x] MVP 错误归因已落代码：timeout/429/网络/provider overload/OOM/context/Docker/service-health -> `infra_error` 且不抬高 Risk；missing required、invalid argument、文件/图层/产物引用不存在等 LLM 工具使用错误 -> `risk=1.0`。
- [ ] 实现 deterministic first-pass scorer，并先做错误归因：
      - OOM / 网络抖动 / timeout / 429 / provider overload / 服务异常 / 上下文不够 -> 标记为 `infra_error`，不更新 ExperienceEvo 的 Q/R/N；
      - 工具报错若由 LLM 明显传错参数、选错工具、引用不存在产物导致 -> `r=0` 且 `risk_observed=1`；
      - 产出有效新 artifact/result -> 部分正分；
      - 产物被下游消费 -> 部分正分；
      - 重复无效调用 / 空产物继续下游 / 参数传反 / 中间结果未完整使用 -> risk。
- [ ] 对模糊样本增加 LongCat checker/subagent。
- [ ] checker 评分维度：
      - 是否完成目标产物；
      - 输入 artifact 是否正确绑定；
      - 输出是否有效 / 非空；
      - 下游消费是否正确；
      - 是否没有编造 path / layer / value；
      - 是否没有 warning/error 后继续无效下游。
- [ ] 有 answer judge 时，用 answer judge 作为 episode-level 信号的一部分；没有时用 tool F1 / success fallback。
- [ ] 每个 `risk_observed=1` 都保存 checker rationale；每个 `infra_error=1` 只进运行日志或 validation log，不进入 Q/R/N 更新。

## Phase 4 - Q/N/R 更新逻辑

- [ ] 实现签名级更新：
      `Qsig = Qsig + alpha * (r - Qsig)`，
      `Rsig = Rsig + alpha_risk * (risk_observed - Rsig)`，
      `Nsig += 1`。
- [ ] 实现工具级更新：
      `Qtool = Qtool + alpha * (r - Qtool)`，
      `Rtool = Rtool + alpha_risk * (risk_observed - Rtool)`，
      `Ntool += 1`。
- [ ] 使用衰减学习率：
      `alpha = alpha0 / sqrt(N + 1)`。
- [ ] 增加 status 转换：
      - candidate -> positive：Q 高、risk 低、N 足够；
      - candidate/positive -> negative：risk 高或 Q 长期低；
      - archive：头部工具重复冗余经验。
- [ ] 增加 Pareto 风格维护：
      保留高 Q、低 risk、长尾覆盖、独特恢复方式经验；压缩头部重复经验。
