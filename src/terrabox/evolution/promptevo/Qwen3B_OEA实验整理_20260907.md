# Qwen 3B OEA 实验整理

更新时间：2026-09-10

## 记录口径

本文整理 2026-09-01 之后 Qwen 2.5 3B Instruct 在 OEA 数据上的实验。指标优先与此前 LaTeX 中的 OEA 字段保持一致；没有实际统计结果的字段记为 `--`，不以零代替。

需要区分训练记录与 OEA 主评测：训练日志中的 reward/parse 指标只反映训练批次；只有将 checkpoint 在固定的 OEA test manifest 上执行真实工具 rollout，才能计算完整 OEA 指标。此前 `n=50` 的 smoke/action 诊断不列入周报主结果。

需要区分两类实验：

1. `eval_actions` 是离线 action 生成诊断，只生成工具调用计划，没有执行真实工具，因此不能解释为完整 OEA success 或最终答案准确率。
2. `online_grpo` 是 veRL 的真实工具在线 rollout + GRPO 训练，工具调用会实际执行；早期在线训练暴露了 CUDA OOM、Ray validation 内存、vLLM sleep 兼容性和 checkpoint CPU OOM 问题，当前已按稳定配置重启并通过多个 checkpoint，尚未产出最终 checkpoint 和正式 OEA test 指标。

## 二、2000 条真实工具在线 GRPO

当前最新在线实验目录：

`tmp/experience_evo_rl/qwen25_3b_pure_online_grpo_tp2_noactoroff_tok8192_util015_full1900_train2000_20260909`

设置为：

- OEA 2000 条：1900 train / 100 val；当前训练覆盖完整 1900 train，最终 OEA test 仍需单独全量评测；
- Qwen 2.5 3B Instruct；
- veRL GRPO + LoRA；
- 真实工具在线执行，启用完整 OEA 工具目录；
- Pure online GRPO baseline，不注入 ExperienceEvo 经验；
- 统一上下文压缩拦截器；
- `CUDA_VISIBLE_DEVICES=2,3`，rollout `TP=2`，工具服务固定在 GPU0/1；
- `max_assistant_turns=12`，`max_tool_response_length=6144`，模型 response 上限 2048；
- `train_batch_size=1`，`rollout_n=2`，`max_steps=1900`，actor / rollout / old-logprob token 上限为 8192；
- `trainer.save_freq=50`，`trainer.max_actor_ckpt_to_keep=1`，并通过 `TERRABOX_VERL_SKIP_OPTIM_CKPT=1` 跳过 optimizer checkpoint，降低 CPU/Ray OOM 风险；
- 原始工具观察、压缩统计、episode trace、reward trace 分开保存。

截至 2026-09-10 02:01，最新 `tp2_noactoroff_tok8192_util015_full1900` 实验已运行到 `training/global_step=206` / progress `207/1900`，已成功保存 `global_step_50/100/150/200`，当前未见 `OOM`、`OutOfMemory`、`CUDA error`、`Traceback`、`RayOutOfMemory` 或 `Killed`。它已经进入稳定运行阶段，但尚未完成完整训练，也没有产出最终 checkpoint，不能进行正式 OEA test 全量评测。

此前失败链路记录如下：`compressed_v4_train2000_20260907` 在 step 0 后因 CUDA OOM 中止；`safe8192_noalloc` 避开 CUDA OOM 后触发 Ray 训练前 validation CPU 内存阈值；`safe8192_valsafe` 验证了 validation 限流但触发 vLLM V1 sleep 兼容性错误；`safe8192_valsafe_keepvllm` 进入真实 rollout 后因真实序列超过 8192 token 上限在 old-logprob 断言失败；`entropyfix_gpu23` 跑到 step 49 后在 step 50 checkpoint 保存 optimizer state 时触发 CPU/Ray OOM。当前版本据此固定 `TP=2`、关闭 actor 参数 offload、降低 response/tool observation 上限、跳过 optimizer checkpoint，并保持完整 train 覆盖。

已保存的部分在线轨迹包括：

- 旧失败目录中的 `metrics/online_episode_traces.jsonl` / `metrics/raw_tool_observations.jsonl`：用于定位失败，不作为正式训练结果；
- 当前目录中的 `metrics/online_episode_traces.jsonl`、`metrics/raw_tool_observations.jsonl`、`metrics/resource_monitor.jsonl`：正在随训练追加；
- `train_online_tmux.log`：记录 veRL 配置、真实工具调用、validation 限流和后续训练状态。

当前近 50 个已记录 step 的过程指标：score mean 约 `0.319`，prompt mean 约 `5185` tokens 且 prompt clip 为 `0`，response mean 约 `951` tokens，response clip ratio 均值约 `0.13`，actor GPU allocated 约 `15.7GB`、reserved 约 `19.0GB`，CPU used 约 `87.9GB`，step 平均约 `181s`。这些指标说明训练、资源和 checkpoint 链路正常；但真实工具慢调用和 2048 response 上限导致的少量截断仍需监控。训练过程诊断不是 OEA test 主结果。

## 三、与此前 OEA LaTeX 指标的对齐说明

此前 LaTeX 主表中的 `Success`、`Set/Multiset F1`、`Exact/Ordered`、`OEA Any/Same/Unique`、`Category F1`、`Tool error`、`Tools/task`、`Tokens/task` 和 `Answer/Gen Acc.`，要求使用完整 OEA rollout 结果计算。

此前的 `n=50` action 诊断只覆盖 action 层字段，本文不将其作为周报结果；2000 条在线 GRPO 当前有真实 rollout 数据，但在独立 test manifest 上完成评测前，也不能把训练集 reward 或 trace 当成 test 指标。

后续正式比较应固定同一个 OEA test manifest，至少跑：

1. Qwen 3B Base，真实工具 standard rollout；
2. Pure GRPO adapter，真实工具 standard rollout；
3. ExperienceEvo + GRPO adapter，真实工具 standard rollout；
4. 在线 GRPO 最终 checkpoint，真实工具 standard rollout。

四组均使用同一套 OEA 指标和同一工具服务配置；缺失的 LongCat answer judge 单独标为 `--`，不影响工具链指标统计。

## 四、周报可直接使用的结论

本周完成了 Qwen 2.5 3B 的离线 QLoRA GRPO 训练，使用 OEA 2000 条数据（1900 train / 100 val），并保存 reward traces、训练日志和 adapter checkpoint。但该 checkpoint 尚未在固定的 1,162 条 OEA test 上执行完整真实工具 rollout，因此完整 OEA 指标目前不能报告，统一记为 `--`。

同时，Qwen 3B 的在线版本已接入真实工具 rollout 和统一上下文压缩机制。当前最新稳定重跑使用完整 1900 条 train 覆盖、`TP=2`、`train_batch_size=1`、`rollout_n=2`、8192 token 训练侧上限、2048 response 上限和跳过 optimizer checkpoint 的安全配置，已通过 step 50/100/150/200 checkpoint。待其产出最终 checkpoint 后，再在固定 OEA test manifest 上做同口径完整评测。
