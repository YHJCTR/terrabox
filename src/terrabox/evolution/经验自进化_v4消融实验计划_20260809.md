# 经验自进化 v4 消融实验计划

> 日期：2026-08-09  
> 目标：验证 ExperienceEvo v4 的收益来自哪些机制，并为中期答辩提供可复现的机制归因表。

## 核心问题

v4 全量结果显示：普通 `answer_acc` 基本持平 Base，但 `answer_acc_w_gen`、工具轨迹、流程成功率和资源成本明显更好。消融实验要回答三个问题：

1. 多 agent verifier/checker 是否真的有收益，而不是只停留在代码设计里。
2. `Quse = lambda * Qtool + (1 - lambda) * Qsig` 的工具排序是否改变工具选择。
3. 工具执行后的逐步产物状态检索是否比任务开始前一次性注入更有效。

## v4 机制流程

```text
OEA train2000 LongCat base rollout
  -> 抽取产物状态转移 family
  -> 统计 Qsig/Nsig/Rsig 与 Qtool/Ntool/Rtool
  -> 构建 v2 JSONL + SQLite store
  -> OEA eval task
      -> 初始 artifact/product state
      -> 检索签名级 transition family
      -> 生成 v4 soft guidance block
      -> LLM 选择工具和参数
      -> 工具执行并更新 product state
      -> step_hint 按当前 state 再检索下一跳 transition
      -> verifier checkpoint 检查缺失证据槽位
      -> 可选 LongCat checker 子 agent 二次审查
      -> 循环直到 final answer / requested artifact
```

## 已实现的消融开关

这些开关只影响 `experience_evo_v4`，默认都关闭，不覆盖 v1/v2/v3 或 v4 主结果。

| 开关 | 默认 | 作用 | 对应消融 |
|---|---:|---|---|
| `TERRABOX_EXPEVO_V4_LLM_CHECKER=1` + `TERRABOX_EXPEVO_V4_LLM_CHECKER_MAX_CALLS=1` | 关闭 | 启用 LongCat verifier 子 agent | `checker_on` |
| `TERRABOX_EXPEVO_V4_DISABLE_QUSE=1` | 关闭 | 保留 transition 和工具候选，但不展示 Quse 排序 | `quse_off` |
| `TERRABOX_EXPEVO_V4_DISABLE_TOOL_RANKING=1` | 关闭 | `DISABLE_QUSE` 别名 | `quse_off` |
| `TERRABOX_EXPEVO_V4_DISABLE_STEP_HINT=1` | 关闭 | 关闭每轮 observation 后的 step-level retrieval | `step_hint_off` |
| `TERRABOX_EXPEVO_V4_DISABLE_VERIFIER=1` | 关闭 | 关闭 deterministic verifier checkpoint 和 LLM checker | `verifier_off` |
| `TERRABOX_EXPEVO_V4_DISABLE_VERIFICATION=1` | 关闭 | `DISABLE_VERIFIER` 别名 | `verifier_off` |

## 指标口径

每组都必须保存三类指标：

1. **答案质量**：LongCat `answer_acc` 和 `answer_acc_w_gen`，这是最重要的最终指标。
2. **工具轨迹**：set/multiset P/R/F1、exact、ordered exact、LCS、OEA Any/Same/Unique、分类别 F1。
3. **效率与稳定性**：completed/failed、has_tool_error、tools/task、LLM/task、tokens/task、time/task。

验收时不看单独 success rate；success 只表示跑完，不代表答对。

## 资源约束

- tau2 低优先级支线仍在跑，消融 watcher 先用单 worker 串行队列，不额外放大 LongCat 压力。
- 外部 LongCat agent 不启动本地 agent vLLM；本地只保留工具/感知服务。
- 外部 API watcher 必须使用 `TERRABOX_TOOL_SERVICE_SCOPE=call` 与 `TERRABOX_KEEP_VLM_WARM=1`。
- 不设置 `TERRABOX_TOOL_GPU_DEVICES`；通过 per-service 环境变量钉卡。
- 保留 `TERRABOX_SERVICE_CALL_LOCKS=1` 与共享 `tmp/service_locks/`，避免多个进程同时撞同一个感知服务。
