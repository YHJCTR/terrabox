# 失败/成功轨迹与产物案例

本文档配合 `cases/` 下的原始 JSON 和图片/GPKG 使用。JSON 保留完整 `conversation_history`、工具调用、观察、指标和进化 trace；下面给出答辩时可直接讲述的完整链路，而不是只给最后分数。

## 1. 感知任务：Base 反复询问，ExperienceEvo 直接绑定可验证工具

### 1.1 任务与输入

问题：`How many buildings are in between domestic and construction waste?`

输入：`TG_40010.jpg`。图像中有 `BUILDING`、`ROAD`、`VEGETATION` 等标注，原始任务要求从图像工具证据中完成建筑相关判断。

### 1.2 Base 完整轨迹

原始文件：`cases/experience_evo/domestic_waste_base_failed.json`。

Base 的实际调用序列为：

```text
1  geo_perception.ocr_extract
2  geo_perception.vlm_analyze
3  geo_perception.vlm_analyze
4  geo_perception.vlm_analyze
5  geo_perception.vlm_analyze
6  geo_perception.vlm_analyze
7  geo_perception.vlm_analyze
8  geo_perception.vlm_analyze
9  geo_perception.vlm_analyze
10 geo_perception.vlm_analyze
11 geo_perception.vlm_analyze
12 geo_perception.vlm_analyze
13 geo_perception.vlm_analyze
14 geo_perception.count_given_object
15 geo_perception.vlm_analyze
```

关键真实观察按时间顺序如下：

1. OCR 返回 `texts=[]`, `count=0`, `full_text=""`。
2. 第一次 VLM 认为没有 domestic/construction waste 标签，无法回答。
3. 后续 VLM 认为没有可见文本，又认为图像是带标注的卫星图。
4. VLM 随后识别出 `BUILDING`、`ROAD`、`VEGETATION`，又在下一轮确认了 `domestic waste` 和 `construction waste` 标签。
5. 对“两个区域之间有多少建筑”的追问先得到“没有建筑”，再次系统检查又得到“没有标签”。
6. 后续 VLM 又报告图像是卫星图/土地利用图，但不能稳定给出建筑数量。
7. 在已经出现多次互相矛盾的自然语言观察后，模型才调用 `count_given_object(image=TG_40010.jpg, text=building)`。
8. 该工具返回：

```json
{
  "status": "success",
  "object": "building",
  "count": 1,
  "bbox": [436.0, 0.0, 690.0, 207.0],
  "score": 0.8106668591499329,
  "output": "Found 1 instance(s) of 'building'."
}
```

9. 模型在最后一次 VLM 后仍未形成最终答案，最终状态是：

```text
ERROR: max sequential tool turns reached before final answer
```

轨迹指标：15 次工具调用；status=failed；sequence F1=.333；multiset-F1=.105；耗时约 299.65s；总 token 104,640。

### 1.3 ExperienceEvo v4 完整轨迹

原始文件：`cases/experience_evo/domestic_waste_v4_success.json`。

运行时先注入的是当前状态约束，而不是历史文件路径或历史答案：

```text
当前状态：input:image, task_request
任务形状：这是对象计数任务；每个请求类别调用 count_given_object 一次。
约束：不要用 vlm_analyze、draw_bboxes 或泛化分割替代返回的 count。
验证器：先取得当前运行的 count 证据，再回答；拒绝空输出和未返回产物。
```

模型随后只调用一次：

```text
geo_perception.count_given_object(
  image="/data1/yuhongjie2/OpenEarthAgent/data/test/TG_40010.jpg",
  object="building"
)
```

工具返回与 Base 后来取得的证据一致：1 个 building，bbox `[436,0,690,207]`，score `.8106668591499329`。随后 `evolution_trace` 记录：

```text
product_state = [input:image, result:from:geo_perception.count_given_object]
verifier = likely_ready
missing_evidence = none
model_decision = final_answer
```

最终答案：当前运行证据显示图中检测到 **1 个 building**，并给出 bbox 与置信度。

轨迹指标：1 次工具调用；status=completed；real_success=true；sequence F1=.500；multiset-F1=.400；耗时约 33.80s；总 token 12,612。

### 1.4 PPT 讲法

左侧展示 Base 的 15 个调用和相互矛盾的 VLM 观察，右侧展示 ExperienceEvo 的 `task_request -> count_given_object -> verified result` 三节点链路；下方放 `299.65s -> 33.80s`、`15 -> 1` 和两段最终状态。重点不是宣称单个案例代表总体，而是说明“产物/任务形状约束如何减少无证据的重复感知调用”。

## 2. GIS 任务：Base 重复建图和错误半径，ExperienceEvo 复用当前产物链

### 2.1 任务与输入

问题：`Assign each park to its nearest museum within a 3000m radius in Kluane National Park, Yukon, Canada.`

### 2.2 Base 完整工具序列与错误

原始文件：`cases/experience_evo/kluane_base_osm_error.json`。

```text
1  osm_gis.get_area_boundary
2  osm_gis.add_pois_layer
3  osm_gis.add_pois_layer
4  osm_gis.add_pois_layer
5  osm_gis.add_pois_layer
6  osm_gis.get_area_boundary
7  osm_gis.get_area_boundary
8  osm_gis.add_pois_layer
9  osm_gis.add_pois_layer
10 osm_gis.compute_route_dist
11 osm_gis.display_on_map
```

实际观察中出现过：

```json
{"status":"error","error_type":"osm_buffer_too_large","message":"buffer_m=50000 exceeds TERRABOX_OSM_MAX_BUFFER_M=10000. Use a smaller radius/buffer or an explicit bbox."}
```

在多次重建 boundary、parks 和 museums 图层后，Base 最终得到 3 个 park 到 3 个 museum/attraction 的距离：

```text
Congdon Creek Territorial Park -> Museum Of Nostalgia: 11574.40 m
Dezadeash Lake Territorial Park -> Museum Of Nostalgia: 50636.72 m
Pine Lake Territorial Park -> Da Ku Cultural Center: 4399.73 m
```

Base 仍然 `status=completed, success=true`，但 `has_tool_error=true`；sequence F1=.857，multiset-F1=.533，耗时约 482.8s。这个案例说明“任务完成标志”不能掩盖中间工具错误和错误/过大参数。

### 2.3 ExperienceEvo v4 的完整产物链

原始文件：`cases/experience_evo/kluane_v4_success.json`。

运行时维护当前产物状态：

```text
task_request
  -> gpkg:from:osm_gis.get_area_boundary
  -> vector_layer:from:osm_gis.add_pois_layer (parks/museums)
  -> result:from:osm_gis.compute_route_dist
```

调用序列只有：

```text
1  osm_gis.get_area_boundary
2  osm_gis.add_pois_layer
3  osm_gis.add_pois_layer
4  osm_gis.add_pois_layer
5  osm_gis.add_pois_layer
6  osm_gis.add_pois_layer
7  osm_gis.compute_route_dist
```

每次注入的经验都要求：绑定当前运行的 `gpkg`，复用工具返回的真实 `layer_name`，拒绝发明路径；在第 6 步 verifier 仍标记缺少数值计算证据，随后检索到 `gpkg + parks + museums -> compute_route_dist` 的当前状态转移；第 7 步得到：

```json
{
  "status":"success",
  "pair_count":1,
  "distances":[12356.58],
  "text":"Dezadeash Lake Territorial Park, Swallow Haven Site, distance=12356.58 m, travel_time=499.9 s",
  "gpkg":"/data1/yuhongjie2/terrabox/tmp/artifacts/gpkg/kluane_boundary.gpkg"
}
```

最终 verifier 状态：`likely_ready`, `missing_evidence=none`。答案明确指出仅发现 Dezadeash Lake Territorial Park，其最近 attraction 为 Swallow Haven Site，路网距离约 12,356.58m，超过 3,000m，因此没有满足半径约束的 park-museum assignment。

轨迹指标：7 次工具调用；sequence F1=1.0；multiset-F1=.727；exact_match=true；耗时约 379.4s；产物为 `kluane_boundary.gpkg` 和 map PNG。注意：该 run 仍有 OSM 工具错误标记，不能描述成“所有工具零错误”；改进点是当前产物绑定、停止条件和最终数值证据更一致。

### 2.4 PPT 讲法

放置 `kluane_v4_map.png`，旁边画出 GPKG 的三层依赖：`area_boundary -> parks/museums -> route distance`。把 Base 的 50,000m 超限错误和 11 次调用放在红色分支，把 v4 的当前 GPKG、真实 layer name 和 12,356.58m 放在绿色分支。

## 3. PromptEvo：Stage2 回归案例

原始指标文件：`raw/promptevo/toolbench/test_base_metrics_summary.json`、`test_stage1_metrics_summary.json`、`test_stage2_metrics_summary.json`。

在同一 n=160 paper split 上：

```text
Base:   success=86.25%, avg_tool_calls=5.14, tool_error=14.37%, no_finish=11.88%
Stage1: success=88.12%, avg_tool_calls=4.67, tool_error=7.50%,  no_finish=11.88%
Stage2: success=84.38%, avg_tool_calls=5.59, tool_error=10.00%, no_finish=15.62%
```

Stage1 的规则补丁改善了调用效率、give-up 和工具错误；Stage2 虽然 give-up=0，但 no-finish、平均调用和 token 开销上升，success 下降。这个反例适合引出 PromptEvo 的核心机制：Stage1 生成候选，Stage2 必须按 paired trace 做行为归因，再经过 typed patch 编译、dev gate 和 regression gate；候选失败就 reject/rollback，而不是强行写入系统提示词。
