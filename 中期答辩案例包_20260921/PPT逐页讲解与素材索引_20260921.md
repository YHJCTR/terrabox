# ExperienceEvo 与 PromptEvo 中期答辩 PPT 逐页说明

本文件对应 `ExperienceEvo_PromptEvo_中期答辩_模板风格副本.pptx`，目标汇报时长约 10 分钟。建议每页讲 45--70 秒，案例页和指标页稍长，其余页面快速过渡。

## 第 1 页：标题页

**主题：**地理空间 Agent 的经验与提示词自进化。

**讲什么：**项目同时研究动态经验（ExperienceEvo）和静态协议补丁（PromptEvo），目标是让多工具 Agent 从真实执行轨迹中改进，而不是只依赖一次性系统提示词。

**时间：**20 秒。

## 第 2 页：汇报目录

**主题：**研究问题、方法、案例、实验和下一步。

**讲什么：**说明汇报顺序，强调后面的实验结果会区分“已完成结果”和“研究计划”。

**时间：**15 秒。

## 第 3 页：研究背景与问题

**核心信息：**工具执行成功不等于任务正确。需要同时关注工具调用、输入产物绑定和输出语义。

**讲解重点：**地理空间任务会产生影像、mask、矢量图层、GeoPackage 等中间产物；错误的文件、时间、对象、单位或 CRS 绑定会在后续步骤中传播。现有完整轨迹记忆和静态提示词难以定位局部缺口。

**建议口播：**“我们要解决的不是单纯的工具选择，而是当前状态下应该消费哪个产物、执行哪一步，以及如何判断这条经验是否适用。”

**时间：**60 秒。

## 第 4 页：ExperienceEvo 产物状态转移经验

**核心流程：**真实 rollout → 轨迹抽取 → 产物状态转移经验 → Q/N/R 与风险排序 → Top-K 检索注入 → 状态验证与停止。

**讲解重点：**经验不是复制完整历史对话，而是记录“输入产物—工具动作—输出产物—后续消费”的局部转移。运行时根据当前 `product_state` 检索经验，工具返回后更新状态，并由 verifier 判断是否已有足够证据。

**要强调：**v4-clean 是运行时经验增强，不是新的 RL 算法；它可以独立用于 Base 或 RL checkpoint。

**时间：**70 秒。

## 第 5 页：Boundary 边界自进化

**核心流程：**经验被使用 → 构造语义保持/语义改变反例 → 输入输出契约审核 → 补充条件、分裂或停用经验。

**讲解重点：**v4-clean 解决“检索什么经验”，Boundary 进一步解决“经验什么时候不应使用”。语义保持变换应保持策略，时间/对象/单位/图层改变则应重新绑定或拒绝复用，从而降低跨任务负迁移。

**当前结论边界：**这是独立模式，可回退到 v4-clean；答辩时应说明正式 OEA 结果以最终报告为准，不把评测中的结果写成已验证提升。

**时间：**60 秒。

## 第 6 页：PromptEvo Stage1/Stage2

**核心流程：**失败轨迹 → Stage1 候选 patch → Stage2 Base/Candidate 对比归因 → typed patch 编译与 dev gate → 接受或回滚。

**讲解重点：**PromptEvo 面向静态、任务无关的协议缺口。Stage1 从失败轨迹提出候选规则；Stage2 通过成对运行比较行为变化，判断候选是否真正减少重复、缺参、工具错误或不终止，并用 typed patch 保证可回滚。

**不要误讲：**Stage2 不是简单让 LLM 自由重写 system prompt，也不保证每次都优于 Base。

**时间：**70 秒。

## 第 7 页：真实案例

**案例：**domestic waste 任务。

**左侧 Base：**OCR 加 13 次 VLM 调用，随后仍未形成稳定证据，15 次调用后达到 max-turn，约 299.65 秒，序列 F1=.333。

**右侧 ExperienceEvo：**当前状态直接绑定输入影像，调用 `count_given_object`，得到 `count=1`、bbox 和置信度，verifier 判断 `likely_ready`，约 33.80 秒完成。

**要表达的因果：**经验提供的不是答案，而是当前产物状态下更短、更可验证的下一步转移。

**素材：**`cases/experience_evo/domestic_waste_base_failed.json`、`domestic_waste_v4_success.json`、`TG_40010.jpg`。

**时间：**75 秒。

## 第 8 页：指标对比

**左侧 PromptEvo：**ToolBench strict split：Base Success 86.25%，Stage1 88.12%，Stage2 84.38%；Stage1 的工具错误率由 14.37% 降至 7.50%。

**右侧 RL：**OEA full test：Qwen3B Base Success 71.86%，Pure GRPO 70.65%，GRPO + ExperienceEvo 73.75%；GRPO + ExperienceEvo 的工具错误率由 Base 的 48.45% 降至 34.17%。

**必须说明：**Set-F1 没有全面提升，Pure GRPO 也没有稳定超过 Base；因此结论应表述为“工具链可靠性和成功率改善”，而不是所有指标 SOTA。

**素材：**`指标汇总_PromptEvo与RL_20260921.md`、`tables/promptevo_all_scenarios.csv`、`tables/rl_vs_qwen3b_base.csv`。

**时间：**90 秒。

## 第 9 页：产物来源感知局部信用分配 GRPO

**定位：**研究计划，不应作为已完成实验。

**核心流程：**完整 rollout 的 episode reward → 产物依赖图 → 输入来源/输出契约/下游消费检查 → 同前缀动作局部对比 → 将局部优势对齐到对应工具调用 token。

**与普通 GRPO 的区别：**普通 GRPO 仍以整条 rollout 计算组内优势，并通常让 assistant token 共享该优势；方案 A 保留 episode advantage，同时只对可信的工具动作 token 加入局部信用。若只把步骤分数相加成总 reward，则只是 reward shaping，不构成算法层面的区别。

**时间：**70 秒。

## 第 10 页：总结与展望

**三句话总结：**ExperienceEvo 把真实轨迹压缩为可验证的产物状态经验；Boundary 学习经验适用边界；PromptEvo 把失败轨迹变成可回滚的协议 patch。

**下一步：**完成 Boundary 公平评测，并在 veRL 中实现产物来源感知的 action-span credit assignment，加入标准 GRPO、过程奖励和局部信用的消融。

**时间：**35 秒。
