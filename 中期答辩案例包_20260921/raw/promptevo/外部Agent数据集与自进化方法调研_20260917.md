# 2026 新 Agent 数据集与 PromptEvo 对比实验计划

## 记录口径

本文整理 2026-09-17 为 PromptEvo 后续实验调研和下载的外部数据集、遥感/地理空间 Agent benchmark，以及可作为对比的 prompt / harness 自进化方法。

当前目标不是马上大规模接入所有 benchmark，而是在 5 天内形成可汇报的、同口径的 PromptEvo 有效性证据：同一 LongCat provider、同一冻结 test manifest、同一 dev 选择规则，比较 Base、普通 prompt 改写、外部自进化 baseline 和我们的 typed protocol patch + protected dev gate。

## 二、最值得接入的新数据集

### GeoNatureAgent：优先级最高

GeoNatureAgent Benchmark 是 2026 年环境地理空间 Agent benchmark，包含 93 个主任务和 10 个扩展任务、18 类能力、16 个工具，任务覆盖 municipality-level analysis、多轮对话、空间推理、跨指标综合、错误处理、排序比较、多语言、栖息地分析和时间变化检测。

它适合作为 PromptEvo 的新场景补充，原因是：

1. 与 Terrabox / OEA 的地理空间工具调用方向一致；
2. 规模小，93 个主任务适合 5 天内先跑 LongCat Base smoke / full；
3. 工具调用和结果评分已经封装在 benchmark 内，接入成本低于重新构造遥感工具链；
4. 当前最强模型也只有约 60% capability，仍有优化空间。

短期建议：先跑 `dev` smoke，确认 LongCat/OpenAI-compatible client 能否接入；如果能跑，再跑 93-task Base。PromptEvo Stage1 是否接入取决于是否能稳定抽取失败轨迹、评分结果和系统 prompt。

### Earth-Agent：第二优先级

Earth-Agent 与地球科学/遥感方向贴近，适合做后续方法扩展或 related work。短期需要先确认其任务格式、工具执行方式和是否依赖外部 API / 本地大模型。若它已经有可复算结果，可以优先做结果表复核，而不是立刻写 PromptEvo adapter。

### 暂不优先的 benchmark

GABench 和 DataAgentBench 当前本地 checkout 不完整，主要原因是服务器缺 `git-lfs`。在完整数据检出前，不建议启动正式实验。AgentGym2、OmniaBench、AgentWebBench 范围大或依赖重，适合后续扩展，不适合 5 天内作为主要结果来源。

## 三、是否需要外部方法对比

需要。否则 PromptEvo 的证据主要是“Base 到 Stage1/Stage2 的变化”，很难说明它优于已有 prompt evolution 或 harness evolution。尤其 2026 年已有 EvoTool、A-Evolve/Evo-Harness、AHO 等方法，单纯说“失败轨迹驱动 prompt 自进化”创新性不够。

建议 5 天内不追求完整复现所有外部方法，而是做一个公平、可解释的最小对比矩阵：

| 方法 | 含义 | 优先级 |
|---|---|---|
| Base / official prompt | 不进化，固定初始 prompt | 必跑 |
| Free whole-prompt rewrite | 让 LLM 基于失败样本自由改完整 prompt | 必跑，证明自由改写容易不稳 |
| SCOPE-style guideline append | 从失败轨迹总结 guideline，直接追加到 prompt，不做 typed patch / gate | P0/P1，成本低，能代表条目式经验更新 |
| GEPA-style reflective mutation | 反思失败轨迹，生成多个候选 prompt，按 dev 选优 | P1，最容易被审稿人认可为强 prompt optimization baseline |
| AHO / BetterHarness prompt-only | 使用 harness optimizer，但关闭 middleware 修改，只改 prompt | P1/P2，作为 harness evolution baseline |
| Ours | typed protocol patch + deterministic compiler + protected dev gate | 必跑 |

对比时必须固定：同一 benchmark、同一 train/dev/test split、同一 LongCat provider、同一限流、同一最大轮次/工具调用预算、同一 dev selection rule。最终 test 只运行一次，不能根据 test 结果反选 prompt。

## 四、我们方法相对 2026 方法的差异

### 与 EvoTool 的差异

EvoTool 把 tool-use policy 分成 Planner、Selector、Caller、Synthesizer 四个自然语言模块，通过 blame-aware mutation 编辑对应模块，并用 diversity-aware selection 保留候选。它和 PromptEvo 很接近，因此论文里必须正面对比。

PromptEvo 当前更适合强调的差异不是“也会归因”，而是：

1. patch 是 typed protocol state，不是自由改写模块 prompt；
2. patch 类型显式覆盖工具选择、参数校验、错误恢复、终止/重复、答案契约、工具输出安全和候选指标保护；
3. deterministic compiler 把结构化 patch 渲染到运行 prompt，保留可审计 provenance；
4. protected dev gate 不只看成功率，还保护错误率、no-finish、give-up、重复调用、工具调用成本和安全指标；
5. 当 Stage2/Stage3 退化时，机制允许拒绝或回退，不把“继续进化”默认当作正向。

### 与 A-Evolve / Evo-Harness 的差异

A-Evolve / Evo-Harness 更像通用基础设施，允许变更 agent workspace、skills、memory、harness 文件。PromptEvo 不应声称比它更泛化，而应定位为低成本、低侵入、面向现有工具型 Agent 的协议层演化方法：不改基础模型、不训练、不大改 runtime，只修改可审计协议状态。

### 与 SCOPE 的差异

SCOPE 从执行轨迹中生成 tactical / strategic guidelines 并追加到 prompt。PromptEvo 可以把它作为“条目式经验追加”baseline，并强调我们的 patch 有类型、作用域、证据、dev gate 和回归保护；不是把所有经验直接塞回上下文。

## 五、5 天内建议执行顺序

### Day 1：补齐现有结果和下载清单

1. 继续等 AgentDojo Stage1/Stage2 LongCat regression-gated 完成；
2. 把 API-Bank 20260914 完整结果追加到 `src/terrabox/evolution/promptevo/20260901后实验周报整理.md`；
3. 保留 GABench/DataAgentBench 的 LFS 缺失备注，不把它们纳入可跑清单；
4. 运行 GeoNatureAgent dev smoke，只验证环境，不作为论文结果。

### Day 2：补方法对比，优先不用新 benchmark

在 API-Bank 或 ToolBench 上先补完整 method ablation：

1. Base；
2. Free whole-prompt rewrite；
3. SCOPE-style guideline append；
4. Typed protocol patch without protected gate；
5. Typed protocol patch + protected gate（ours）。

这组比新增 benchmark 更重要，因为它直接证明 PromptEvo 的机制贡献。

### Day 3：AgentDojo 汇总与失败解释

AgentDojo 完成后，若 Stage1/Stage2 没有提升，应诚实写作安全-效用权衡和 adapter/benchmark 特性分析；不要只挑 balanced score。若 protected gate 拒绝回退 prompt，反而可以作为“回归安全”的论据。

### Day 4：GeoNatureAgent Base / Stage1 试跑

如果 dev smoke 通过，跑 93-task LongCat Base；再决定是否接 PromptEvo Stage1。若接入成本超过预期，停止在 Base + 可行性分析，不临时拼一个不可信 adapter。

### Day 5：形成汇报表

周报/汇报表建议使用两张表：

1. Benchmark 维度：API-Bank、ToolBench、AgentDojo、GeoNatureAgent smoke/Base；
2. Method 维度：Base、free rewrite、guideline append、GEPA/SCOPE/AHO baseline、Ours。

主结论应写成：PromptEvo 的价值不是“每个 Stage 都涨”，而是在工具型 Agent 中把失败更新约束成可审计、可回退、受保护的协议补丁；在 API-Bank 和 ToolBench 上已看到正向或局部正向，在 AgentDojo 这类安全攻击场景上需要更严格的安全 gate。

## 六、当前风险与注意事项

1. 不要把 GABench/DataAgentBench 作为已完整下载；当前缺 `git-lfs`。
2. 不要把外部方法论文表里的数值直接当作我们的复现实验结果。
3. 不要让 AHO full middleware 与 PromptEvo prompt-only 直接比较；若 AHO 能改 middleware，需单独标注能力面不同。
4. 不要用最终 test 结果选择 prompt；dev gate 通过后再跑 frozen test。
5. 当前 LongCat 只有 PromptEvo 使用时，不设置 workload fair queue；只保留服务端节流，避免额外排队。
6. AgentDojo 仍在运行时，不要启动会抢同一 LongCat 限流的大型 PromptEvo 任务；可以做本地文档、adapter smoke 或不消耗 API 的准备工作。
