# 自进化 Agent 投稿证据包模板

本模板服务于 `paper/self_evolving_agents/experienceevo_v4/` 与 `paper/self_evolving_agents/promptevo/` 的最终落表。它不是实验脚本，也不替代 `results/<task_id>.json` 这一原始记录；用途是在实验结束后将可审计的派生统计、配置和人工审计整理为一个随论文发布或可供审稿人核验的证据包。

## 通用目录结构

每个最终比较使用独立、不可覆盖的目录。目录名应包含论文方法、环境、模型、split hash 和日期，例如：

```text
release_evidence/
  experienceevo_v4_oea_longcat_<split-hash>_<date>/
    README.md
    manifest.json
    split_manifest.json
    tool_manifest.json
    environment_manifest.json
    raw_result_locations.json
    task_metrics.jsonl
    paired_comparisons.csv
    bootstrap_summary.json
    failure_accounting.json
    answer_audit.csv
    artifact_audit.csv
    experience_audit.jsonl
    tables_for_paper.csv
  promptevo_<environment>_<model>_<split-hash>_<date>/
    README.md
    manifest.json
    split_manifest.json
    prompt_fingerprints.json
    candidate_ledger.jsonl
    compiler_reports.jsonl
    task_metrics.jsonl
    paired_comparisons.csv
    bootstrap_summary.json
    failure_accounting.json
    security_or_contract_audit.csv
    tables_for_paper.csv
```

绝不复制密钥、完整私有输入、用户身份、精确私有路径或原始攻击载荷到公开证据包。对这些字段使用稳定的哈希、相对路径或经审查的脱敏摘要。公开前应确认 raw results 的访问控制与数据许可证。

## 通用 Manifest

`manifest.json` 是每一张论文主表行的配置证明。所有对比行都应有该文件，且先生成再运行。最小字段如下：

```json
{
  "paper": "experienceevo_v4 | promptevo",
  "condition_id": "stable, human-readable identifier",
  "condition_role": "base | control | ablation | proposed | baseline",
  "created_at": "ISO-8601 timestamp",
  "code_commit": "git commit or explicit dirty-tree digest",
  "dataset_name": "benchmark and release",
  "task_split_hash": "sha256",
  "task_count_planned": 0,
  "task_count_scored": 0,
  "actor_provider": "provider identifier",
  "actor_model": "model revision",
  "actor_sampling": {"temperature": null, "top_p": null, "seed_policy": "..."},
  "tool_manifest_hash": "sha256",
  "prompt_fingerprint": "sha256 or null",
  "retry_policy": {"max_transient_retries": 0, "restart_full_trajectory": true},
  "timeout_policy": {"agent_seconds": null, "tool_seconds": null},
  "cache_policy": {"enabled": true, "cache_version": "..."},
  "workers": 0,
  "resource_policy": {"max_iterations": null, "service_scope": "..."},
  "evaluator": {"name": "...", "model": "...", "independent_of_actor": false},
  "raw_results": "relative or controlled location",
  "notes": "known deviations, including adapted baseline differences"
}
```

`split_manifest.json` 至少记录 train/dev/test 的 task ID 哈希、数量、生成规则、彼此不相交的检查结果和 final-test 是否被使用过。`tool_manifest.json` 记录可见 tool slug、参数 schema 哈希、mock 状态和每个外部服务的版本/镜像摘要。若任一项不同，两个条件不能被当成同一主表内的直接配对对比；应先解释差异，或重新运行。

## 任务级统计与失败核算

`task_metrics.jsonl` 每个计划任务一行，包括失败和空 final。推荐字段：

```json
{
  "task_id_hash": "stable redacted identifier",
  "condition_id": "...",
  "split": "train | dev | test",
  "terminal_status": "completed | failed | empty_final | evaluator_error",
  "success": false,
  "tool_set_f1": null,
  "tool_multiset_f1": null,
  "tool_exact": false,
  "tool_ordered_exact": false,
  "ordinary_answer_scored": false,
  "ordinary_answer_correct": null,
  "generated_artifact_requested": false,
  "generated_artifact_completed": null,
  "tool_calls": 0,
  "llm_calls": 0,
  "input_tokens": 0,
  "output_tokens": 0,
  "wall_time_seconds": null,
  "invalid_call_count": 0,
  "repeated_call_count": 0,
  "retry_count": 0,
  "failure_class": "none | agent | tool_contract | infrastructure | evaluator",
  "raw_result_sha256": "..."
}
```

`failure_accounting.json` 汇总 planned、found、scored、completed、failed、empty-final、transient retry exhausted、evaluator error、人工审计缺失和每一种排除的数量。任何从主指标分母排除的情况都必须有预先声明的规则和数量；不能因为输出不完整、超时或答案难判而静默删除。

`paired_comparisons.csv` 一行对应一个共同 task ID。应含 base/proposed 指标、差值、两边状态和配对是否有效。`bootstrap_summary.json` 应记录重采样次数、随机种子、置信区间类型、分母、缺失处理、每个主指标的点估计与区间。测试集只用于最终冻结版本，不能反复用于选择补丁、阈值或消融开关。

## ExperienceEvo v4 专用证据

ExperienceEvo 的关键问题不是“结果是否变好”而是“改变来自已学习的 transition family、继承 fallback，还是通用 runtime guard”。每次正式运行必须额外保存以下字段：

```json
{
  "task_id_hash": "...",
  "step_index": 0,
  "product_state_before": ["typed state token"],
  "retrieved_family_ids": ["..."],
  "family_provenance": ["train_rollout | experience_evo_v3_runtime_fallback"],
  "learned_candidate_family_ids": ["..."],
  "fallback_priority_applied": false,
  "learned_ranking_suppressed_by_fallback": false,
  "recommended_tools": ["tool slug"],
  "selected_tool": "tool slug or null",
  "selected_in_recommendations": null,
  "binding_check": "pass | fail | not_applicable",
  "product_contract_check": "pass | fail | not_applicable",
  "guard_event": "none | image_path | calculator_syntax",
  "verifier_status": "..."
}
```

`experience_audit.jsonl` 至少同时给出：learned-family 可用率、fallback-family 覆盖率、fallback 优先级触发率、fallback 对 learned ranking 的抑制率、无 family 覆盖率、推荐命中率、在命中条件下的 current-run binding 有效率，以及按 returned family provenance 分层的任务成功和产物完成率。不要将 fallback 的使用混入“rollout-derived experience coverage”。

当前 v4 的通用 guidance 文本会把检索到的 lesson 统一称为 rollout-derived，而实际 `retrieve()` 会在 fallback 非空时先返回 `experience_evo_v3_runtime_fallback`，不再继续 ordinary learned-store ranking。同时，现有通用 `evolution_trace` 仅保存 recommendation-level 信息，未保存 family ID 或 provenance。正式证据包生成前必须先修正该文本并扩展实际 trace；不能用运行后根据 tool 名猜测 provenance 的方式补写审计字段。

最终主比较至少应有以下条件，并共享同一 test task hash、actor、工具 manifest、重试/缓存/资源策略：

| 条件 | Store | Soft guidance | Generic guard | 作用 |
|---|---:|---:|---:|---|
| Base | 否 | 否 | 否 | 未增强基线 |
| Base + generic guard | 否 | 否 | 是 | 隔离窄口径工程保护 |
| No-store soft-only | 否 | 是 | 是或显式固定 | 隔离无经验的状态/验证语言 |
| Learned-store-only | 是 | 是 | 显式固定 | 禁用或单独报告 v3 runtime fallback |
| Full v4 | 是 | 是 | 是 | 实际完整系统 |

若无法实现 learned-store-only，主张必须收缩为 product-state guidance runtime，而不是纯 train-rollout experience transfer。`tables_for_paper.csv` 应把 ordinary answer、generated-artifact completion、工具指标和资源指标分列，不能以混合得分掩盖其中之一。

## PromptEvo 专用证据

PromptEvo 的一个候选只有在固定 development rollout 通过预注册接受门后才可称为 accepted。`candidate_ledger.jsonl` 必须保留每个候选，包括未 rollout、编译拒绝和 dev 拒绝者：

```json
{
  "cycle_id": "...",
  "parent_prompt_fingerprint": "...",
  "candidate_id": "...",
  "mode": "legacy | typed_patch",
  "candidate_prompt_fingerprint": "...",
  "evidence_batch_ids": ["redacted trace batch IDs"],
  "patch_evidence": [
    {"patch_id": "...", "declared_evidence": ["..."], "trace_or_attribution_ids": ["..."]}
  ],
  "evidence_resolved": true,
  "evidence_resolution_errors": [],
  "diff_summary": "...",
  "patch_kinds": ["tool_selection"],
  "patch_count": 0,
  "compiler_status": "accepted | rejected | warning",
  "compiler_reasons": ["..."],
  "dev_task_split_hash": "...",
  "dev_rollout_status": "not_run | complete | incomplete",
  "primary_metric_before": null,
  "primary_metric_after": null,
  "protected_metrics_before": {},
  "protected_metrics_after": {},
  "thresholds": {},
  "accepted": false,
  "decision_reason": "...",
  "reviewer_id_hash": "..."
}
```

当前 `protocol_patch.py` 对 `evidence` 只做字符串列表规范化：字段缺失时默认空列表，且不会验证字符串是否可回溯到 trace 或 attribution。因此 `evidence_batch_ids` 不能替代 patch 级证据。正式 typed-patch 运行必须在 candidate ledger 生成层强制：每个进入 dev rollout 的 patch 具有非空 `declared_evidence`，并至少有一个可解析的、版本化的 `trace_or_attribution_ids`；不能解析者应以 `evidence_resolved=false` 留在 ledger 中且不得进入 dev 接受。发布时保留脱敏的 ID 映射、解析规则和人工抽查结果，不能只保存自由文本。

`compiler_reports.jsonl` 记录 parser/validator/compiler 版本、被拒绝的 task/path/benchmark 或结构性模式、placeholder/dynamic anchor 检查、high-risk withholding 和人工复核结论。禁止把“编译成功”或“带有 evidence 字段”当作安全、通用、trace-backed 或有效的证明。

论文当前的多指标接受公式要求 primary 和全部 protected metric 均在阈值内。若最终实现仍仅用 `success_rate` 接受候选，论文方法、表格、摘要和补充材料必须改写为单指标门；不能把未执行的 protocol 当成实现保证。对于安全环境，utility、security、attack success、成本和基础设施失败率应分别报告，且 no-update control 与每个候选使用同一评测政策。

## 落表与发布检查

在把数字从证据包填入 `main.tex` 前，逐项确认：

1. 每个数字可回溯到 `task_metrics.jsonl`、manifest 和 raw results；主表分母一致或差异已写明。
2. 所有 baseline 被标注为 `official`、`adapted` 或 `reimplemented`，并提供来源、commit、接口变化和限制。
3. 所有 test-set 数字在 prompt/threshold/ablation 冻结后仅计算一次；开发搜索记录没有被删除。
4. 每个核心均值有配对不确定性区间或另一种适当的、预先声明的统计检验。
5. actor 与 LLM judge 同源时，ordinary-answer 结论有独立 judge 或盲审人工子集；生成产物采用单独的 artifact contract 指标。
6. 论文摘要、结果、讨论、结论只陈述证据包实际支持的范围；负结果、已知配置差异和机制失败不得删除。
7. 使用目标会议模板在 Overleaf 编译，检查 TikZ 图、宽表、引用、匿名信息、许可证和补充材料链接。

完成这些检查后，才能将主稿中的 `TBD` 替换为最终数字，并将本模板对应的证据包归档为可引用版本。
